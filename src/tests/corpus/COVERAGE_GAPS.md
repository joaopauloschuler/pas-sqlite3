9.1.6.followup categorization).  Each row is an opcode in
`passqlite3vdbe.pas` that the corpus does not exercise *and*
that is allow-listed by `IsCoverageGap` in
`src/tests/TestSQLCorpus.pas`.

Every row is tagged **(a) gated on an unported feature or
planner-shape heuristic** — the reason column cites the
Phase 6/7/8/10 bullet that gates the emit path.  When that
bullet closes, drop the opcode from `IsCoverageGap` and add
a targeted .sql to the inline coverage-driver set in
`TestSQLCorpus.pas`.  The (b) "reachable-now" entries from
the previous list (IsTrue, MemMax, plus the four real-cold
opcodes String / RealAffinity / Pagecount / MaxPgcnt) have
been driven hot by new cv14..cv17 scripts.

Cold opcodes that are NOT in the allow-list fail the gate (rc=1)
— those are real corpus gaps and must be closed with a script.
