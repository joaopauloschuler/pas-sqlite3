# corpus/MANIFEST.txt — task 9.1.1 (Phase 9 corpus inventory)
#
# This MANIFEST enumerates every source-of-truth file that contributes SQL
# statements to the existing Diag*/Test* differential gates.  In this port
# the corpus is carried as *embedded SQL string literals inside .pas files*
# rather than free-standing .sql files on disk — `find src/tests -name
# '*.sql'` returns zero hits, and shell-driven harnesses (TestShell*) write
# their .sql scratch files into the workdir at runtime via SysUtils.GetTempDir
# (those scratch files are not source corpus and are excluded).
#
# TestSQLCorpus.pas (Phase 9.1.3) will share these same source files — it
# must NOT copy them.  For each entry we record:
#
#   path<TAB>tag<TAB>note
#
# `path` is relative to repo root.
# `tag` is one of:
#   ddl       CREATE/DROP TABLE/INDEX (no ALTER)
#   alter     ALTER TABLE (rename/add/drop column)
#   dml       INSERT/UPDATE/DELETE
#   dql       SELECT-heavy probe (joins, subselects, expressions)
#   pragma    PRAGMA workload
#   txn       BEGIN/COMMIT/ROLLBACK/SAVEPOINT
#   trigger   CREATE TRIGGER + fire path
#   view      CREATE VIEW
#   cte       WITH ... AS recursive/non-recursive
#   window    OVER(...) window-function clauses
#   json      json1 family
#   vacuum    VACUUM / INTO
#   mixed     multi-tag corpus (annotate dominant categories in note)
#
# `note` is one short clause: cardinality, whether it overlaps the 1026-row
# TestExplainParity differential, and the dominant SQL families.
#
# Cardinality reference (TestExplainParity.pas:N_CORPUS = 983+3+4+15+21 = 1026).
# The other large corpora (TestWhereCorpus, TestBytecodeParity, TestParser)
# are tagged "subset/overlap" where their SQL families are already covered
# by the TestExplainParity 1026-row matrix; TestSQLCorpus should treat
# TestExplainParity as the spine and pull the dialect-specific corners
# (PRAGMA, TXN, TRIGGER, VIEW, WINDOW, JSON, VACUUM, ALTER) from the Diag*
# files because the parity tests deliberately skip statements whose plans
# are non-deterministic or run-time only.
