Reference vector inventory (tasklist 9.2.1).
=============================================

Each vector is a `.db` blob produced from a sibling `.sql` script by
the C reference shell (`../sqlite3/sqlite3`).  Re-running
`./regen.sh` (tasklist 9.2.5) must reproduce every committed `.db`
byte-identically.  All blobs were generated against:

    SQLite 3.53.0 2026-04-09 (../sqlite3/sqlite3)

Status legend: [X] complete  [~] partial / known-limited  [SKIP] script
only, no .db committed (extension not yet ported).  `pas-skip` (column
3) marks vectors the Pascal port currently fails on under the 9.2.x
parity probes — see `DIVERGENCES.md` for the bucket and citation.
The 9.2.x gates skip pas-skip vectors so the binary still rc=0.

Phase-6/7/8 column links each vector to the Phase tasklist bullet that
will (or already does) consume it.  Vectors without a direct gate are
marked "general".

Notes for future agents
-----------------------

* Do NOT regenerate `simple.db` / `multipage.db` casually — they pin
  Phase 3 pager-test expectations.  If the C oracle ever changes the
  on-disk layout for these schemas, bump the test fixtures together.

* `wal.db` carries WAL mode in its header (bytes 18..19 = 02 02) but
  has no live frames; the C shell's clean shutdown final-checkpoints
  and removes the .db-wal sidecar.  A truly mid-checkpoint vector
  would require crashing the writer between PASSIVE checkpoint and
  exit, which is not portable across kernels — flagged here so the
  Phase 9 read-only probe can still exercise the WAL header path
  without depending on the sidecar.

* `fts5.db` and `rtree.db` are intentionally absent.  The Phase 8
  tasklist marks the matching extensions as out-of-scope until the
  upstream `ext/fts5/` and `ext/rtree/` trees are ported.  When those
  ports land, drop the [SKIP] tag here, run `./regen.sh`, and commit
  the new blobs alongside.

* All scripts must remain executable by `sqlite3 file.db < file.sql`
  with no extra flags.  Shell-only directives (`.filectrl`, `.read`)
  are allowed because the script flows through the shell, not raw
  libsqlite.

9.2.x pas-skip overrides
------------------------

Vectors listed below are tagged `pas-skip` for the 9.2.x parity probes
(read-only / round-trip / schema-change).  The probes (e.g.
`bin/TestVectorReadOnly`) skip these so the binary still exits rc=0;
each line cites the divergence bucket in `DIVERGENCES.md`.

Bucket A (read-only schema-init) gates 9.2.2 / 9.2.3 only.  9.2.4
opens RW so it does not inherit bucket-A; 9.2.4-specific buckets are
B/C/D/E below and gate 9.2.4 alone.

  pas-skip simple.db           bucket-A (read-only schema-init)
  pas-skip multipage.db        bucket-A
  pas-skip wal.db              bucket-A
  pas-skip autovacuum.db       bucket-A,bucket-B (VACUUM EAccessViolation)
  pas-skip incrvacuum.db       bucket-A
  pas-skip utf16.db            bucket-A
  pas-skip withoutrowid.db     bucket-A,bucket-D (CREATE INDEX byte layout on WITHOUT ROWID)
  pas-skip generated-column.db bucket-A
  pas-skip triggers.db         bucket-A
  pas-skip view-cte.db         bucket-A,bucket-C (ALTER RENAME with dependent VIEW/CTAS — EAccessViolation)
  pas-skip partial-index.db    bucket-A,bucket-E (ALTER RENAME COLUMN on table with partial index)

Reproducibility gate
--------------------

`./regen.sh` (tasklist 9.2.5) iterates every `*.sql` here, regenerates
the `.db` into a tempdir, and `cmp`s against the committed blob.  Any
mismatch (other than for [SKIP] entries) is a hard failure.
